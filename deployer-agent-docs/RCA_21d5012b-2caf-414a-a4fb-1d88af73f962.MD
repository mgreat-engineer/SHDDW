# RCA — Shadow (polar-mimic): "request failed with status 500"

## Summary
The deploy pipeline succeeded and the app is LIVE (https://polar-mimic.emergent.host, `/` + `/health` return 200). The 500s are a **runtime** error on the browser endpoints: the production image has **no Chromium browser binary installed**. Playwright is present as a Python package, but the browser executable it needs was never downloaded into the image. Your suspicion is confirmed.

## Which endpoints / which traceback
12× HTTP 500 observed, all on the two Playwright endpoints:
- `GET /api/browser/frame` → `server.py:176` (`browser_frame`)
- `GET /api/browser/state` → `server.py:168` (`browser_state`)

Call chain (both):
`session(uid)` → `shadow_browser.get_session` (`shadow_browser.py:618`) → `BrowserSession.start` (`shadow_browser.py:237`) → `pw.chromium.launch_persistent_context(...)`

Exact exception (from prod logs, run 21d5012b):
```
playwright._impl._errors.Error: BrowserType.launch_persistent_context:
Executable doesn't exist at /root/.cache/ms-playwright/chromium_headless_shell-1248/chrome-headless-shell-linux-arm64/chrome-headless-shell
╔════════════════════════════════════════════════════════════╗
║ Please run the following command to download new browsers:  ║
║     playwright install                                       ║
╚════════════════════════════════════════════════════════════╝
```

## Root cause (proven)
- `backend/requirements.txt` pins `playwright==1.64.1` — installs the Python package only, **not** the browser binaries.
- Neither `Dockerfile`, `Dockerfile.cloudbuild`, nor `entrypoint.sh` contain any `playwright install`, `chromium`, or Chrome `apt` step (grep across all three returned nothing). So the arm64 image ships with no browser.
- CHROME_PATH behaviour (`shadow_browser.py:615`): `executable_path` is used only if `CHROME_PATH` is set **and the path exists**. The secret is set (non-empty) but `/usr/bin/google-chrome` does not exist in the prod image, so the code correctly falls back to Playwright's bundled Chromium — which is also not installed. **Neither Chrome nor bundled Chromium is present.**

I could not run a real WS upgrade handshake end-to-end (no WS client tool, and this is a Cloudflare frontend so the worker must proxy the upgrade), so full upgrade connectivity is UNVERIFIED, but the backend route exists and is mounted.

## Fix (Code / E1 — requires redeploy)
Add a Playwright browser install to the production build so the arm64 image contains the browser. In `Dockerfile.cloudbuild` (the file that builds the runtime image), after pip install:
```
RUN python -m playwright install --with-deps chromium
```
Notes:
- Must match `playwright==1.64.1`; `--with-deps` also pulls the required system libraries.
- This installs the bundled Chromium at the `ms-playwright` cache path the error references — the code's fallback will then find it even with `CHROME_PATH` unset/invalid.
- Alternative (if you specifically want Google Chrome at `/usr/bin/google-chrome`): install it via apt and keep `CHROME_PATH`. On **arm64**, stable Google Chrome is not readily available via apt — Playwright's bundled Chromium is the simpler, arch-correct choice. If you go the chromium route, you can leave `CHROME_PATH` as-is (the fallback handles it) or clear it in the Secrets tab.

This is the only confirmed cause of the reported 500s. No secret, DB, tier, or domain issue is involved.
